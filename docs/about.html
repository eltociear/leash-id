Leash ID lets an AI agent pay invoices and buy services on ME Network, but only inside a spending leash tied to its owner's live, KYC-backed ME ID. A contract on ME Hub re-reads that ME ID on every payment. Suspend it, and every agent under it stops in the next block.

How it works

1 · The owner sets a leash

An owner with an ME ID (KYC level ≥ 2) offers a leash to an agent key: per-payment and 24-hour limits, which vendors, when a payment waits for approval (by one or two signers), when it expires. The agent key accepts it.

2 · The agent pays

Claude, or any agent, works an invoice inbox through our MCP server. Each payment is a transaction from the agent key, and nothing else it holds can touch the budget.

3 · The contract checks

Is the owner's ME ID still active? Is the vendor allowed or verified? Within limits? Paid before? Over the threshold? Every check runs on chain, in one transaction, with no oracle.

Built on what only ME Network has

ME ID on chain

/metaearth.did.Query/Did from inside the contract, on every pay, approve and whois. The ME ID is the kill switch.

EVM sub-accounts and bonds

Sub-accounts bound in x/did count as their ME ID (shown on testnet with real records). Fixed deposits can back an owner as a bond.

multi_send, in MEC

Batches settle through ME Hub's own multi_send. Receipts carry both parties' ME IDs.

For sellers too

An API can sell to AI agents only when a verified human answers for them: HTTP 402 terms, payment through the leash, and a signed proof from the paying agent. Replays, front-running and sellers without an ME ID all fail. How to add it.
